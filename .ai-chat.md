# Clockwork Offloader - AI Chat Context

This document provides context and logic about the Clockwork Offloader plugin for future AI chat sessions.

## Plugin Overview

**Clockwork Offloader** is a WordPress plugin that offloads media files to S3-compatible storage (AWS S3 and DigitalOcean Spaces) with optional URL rewriting, delete-after-upload, bulk migration tools, and restore functionality.

### Supported Providers
- **AWS S3** (`aws`) - Amazon Web Services S3
- **DigitalOcean Spaces** (`digitalocean`) - S3-compatible storage

**Note**: Cloudflare R2 and Google Cloud Storage support has been removed to reduce plugin bloat. Only AWS S3 and DigitalOcean Spaces are supported.

## Architecture

### Core Classes

1. **`Clockwork_Offloader`** (main plugin file)
   - Singleton pattern
   - Loads dependencies and initializes hooks
   - Handles activation/deactivation
   - Creates database tables on activation

2. **`Clockwork_Offloader_Tracker`** (`includes/class-offload-tracker.php`)
   - Manages database tracking of offloaded files
   - Database table: `wp_cloudbound_offloads`
   - Key methods:
     - `record_offload()` - Records an offload in the database
     - `is_offloaded()` - Checks if attachment is offloaded
     - `get_s3_url()` - Gets S3 URL for an attachment
     - `get_statistics()` - Gets offload statistics (cached for 5 minutes)

3. **`Clockwork_Offloader_S3_Service`** (`includes/class-s3-service.php`)
   - Handles S3 uploads/downloads using AWS SDK v3
   - Supports AWS S3 and DigitalOcean Spaces
   - Key methods:
     - `get_provider()` - Returns 'aws' or 'digitalocean'
     - `get_credentials()` - Gets credentials from wp-config.php or database
     - `get_s3_client()` - Returns configured S3 client
     - `upload_file()` - Uploads file to S3
     - `download_file()` - Downloads file from S3
     - `construct_file_url()` - Constructs S3/CDN URL

4. **`Clockwork_Offloader_Settings_Helper`** (`includes/class-settings-helper.php`)
   - Centralizes settings management with multisite support
   - Settings priority: wp-config constants > network settings > site settings > defaults
   - Key methods:
     - `get_settings()` - Gets settings with proper hierarchy
     - `get_network_settings()` - Gets network-wide settings (multisite)
     - `get_site_settings()` - Gets site-specific settings
     - `is_network_mode_enabled()` - Checks if network mode is active
     - `set_network_mode()` - Toggles network-wide mode
     - `update_network_settings()` - Updates network settings
     - `update_site_settings()` - Updates site settings
     - `is_configured()` - Checks if plugin is configured
     - `get_settings_source()` - Returns source of settings (for debugging)

5. **`Clockwork_Offloader_URL_Rewriter`** (`includes/class-url-rewriter.php`)
   - Rewrites WordPress media URLs to point to S3/CDN
   - Hooks:
     - `wp_get_attachment_url` (priority 10)
     - `wp_get_attachment_image_src` (priority 10)
     - `wp_calculate_image_srcset` (priority 10)
     - `image_downsize` (priority 5 - runs before WordPress checks for local files)
   - **Critical**: If a file is marked as offloaded in the database, it ALWAYS uses the S3 URL, regardless of local file existence

6. **`Clockwork_Offloader_Admin`** (`includes/class-admin.php`)
   - Admin interface and AJAX handlers
   - Setup wizard for initial configuration
   - Dashboard with statistics
   - Settings page
   - Development Mode page with diagnostic tools

7. **`Clockwork_Offloader_Bulk_Offloader`** (`includes/class-bulk-offloader.php`)
   - Handles bulk offloading operations
   - Processes attachments in batches
   - Uses queue system for large operations

8. **`Clockwork_Offloader_Queue`** (`includes/class-queue.php`)
   - Queue system for batch uploads
   - Database table: `wp_cloudbound_offload_queue`
   - Statuses: 'pending', 'processing', 'completed', 'failed', 'cancelled'

## Database Schema

### `wp_cloudbound_offloads` Table
```sql
- id (BIGINT, PRIMARY KEY)
- attachment_id (BIGINT, indexed)
- bucket (VARCHAR(255))
- s3_key (VARCHAR(512)) - Full S3 path including wp-content/uploads/ prefix
- original_path (VARCHAR(512)) - Original local file path
- file_size (BIGINT)
- offload_date (DATETIME)
- status (ENUM: 'offloaded', 'restored', 'deleted')
- size_name (VARCHAR(100)) - Image size name (empty string for original)
```

**Indexes:**
- `attachment_id`
- `status`
- `size_name`
- `attachment_status` (attachment_id, status)
- `attachment_size_status` (attachment_id, size_name, status)
- `status_offload_date` (status, offload_date)

**Important**: Each image size (thumbnail, medium, large, etc.) has its own record with a unique `size_name`. The original file uses an empty string `''` for `size_name`.

### `wp_cloudbound_offload_queue` Table
```sql
- id (BIGINT, PRIMARY KEY)
- attachment_id (BIGINT, indexed)
- status (ENUM: 'pending', 'processing', 'completed', 'failed', 'cancelled')
- priority (INT)
- attempts (INT)
- error_message (TEXT)
- created_at (DATETIME)
- updated_at (DATETIME)
```

## S3 Key Path Structure

**Critical**: S3 keys must include the `wp-content/uploads/` prefix to match actual S3 bucket structure.

Example:
- Local path: `/wp-content/uploads/2025/12/image.jpg`
- S3 key: `wp-content/uploads/2025/12/image.jpg` (NOT just `2025/12/image.jpg`)

This is important for:
1. URL construction (CDN paths match S3 structure)
2. Migration from other plugins (some plugins may store paths without prefix)
3. File verification and restoration

## URL Construction

### AWS S3
- **Format**: `https://{bucket}.s3.{region}.amazonaws.com/{s3_key}`
- **CDN (CloudFront)**: Uses custom domain if configured, otherwise S3 URL

### DigitalOcean Spaces
- **Format**: `https://{bucket}.{region}.digitaloceanspaces.com/{s3_key}`
- **CDN**: Uses custom domain if configured, otherwise Spaces URL

### Region Handling
- AWS S3: Uses region from settings (e.g., `us-east-1`, `us-east-2`)
- DigitalOcean Spaces: Uses region from settings (e.g., `nyc3`, `sfo3`)
- **Important**: The region stored in the database record should match the actual bucket region to avoid `PermanentRedirect` errors

## Credential Storage

### Priority Order
1. **wp-config.php constants** (recommended for security):
   - `CLOUDBOUND_OFFLOADER_AWS_ACCESS_KEY`
   - `CLOUDBOUND_OFFLOADER_AWS_SECRET_KEY`
   - `CLOUDBOUND_OFFLOADER_AWS_REGION` (optional)
   - `CLOUDBOUND_OFFLOADER_AWS_BUCKET` (optional)
   - `CLOUDBOUND_OFFLOADER_PROVIDER` (optional: 'aws' or 'digitalocean')

2. **Database settings** (fallback):
   - Single-site: Stored in `wp_options` table as `cloudbound_offloader_settings`
   - Multisite (network mode): Stored in `wp_sitemeta` as `cloudbound_offloader_network_settings`
   - Multisite (per-site): Stored in `wp_X_options` as `cloudbound_offloader_settings`
   - Less secure but easier to manage through admin

### Credential Storage Methods
The plugin supports two methods for storing credentials:
- **wp-config.php**: Credentials defined as constants (highest priority, most secure)
- **Database**: Credentials stored in WordPress options (easier to manage, less secure)

The setup wizard and migration tool allow users to choose their preferred method.

## URL Rewriting Logic

The URL rewriter uses a simple rule: **If a file is marked as offloaded in the database, always use the S3 URL**.

This means:
- Even if the local file exists, the S3 URL is used
- No conditional checks for local file existence
- The database is the source of truth

**Hooks used:**
- `wp_get_attachment_url` - Main attachment URL
- `wp_get_attachment_image_src` - Image src attribute
- `wp_calculate_image_srcset` - Responsive image srcset
- `image_downsize` - Image downsize (priority 5 to run early)

## Security Standards

All code follows WordPress security best practices:

1. **Nonce Verification**: All AJAX handlers verify nonces using `check_ajax_referer()`
2. **Capability Checks**: All admin actions check `current_user_can('manage_options')`
3. **Input Sanitization**: All user input sanitized using:
   - `sanitize_text_field()` for text
   - `absint()` for integers
   - `wp_unslash()` for POST data
4. **Output Escaping**: All output escaped using:
   - `esc_html()` for HTML content
   - `esc_attr()` for attributes
   - `esc_url()` for URLs
5. **SQL Injection Prevention**: All queries use `$wpdb->prepare()` and `esc_sql()` for table names
6. **File Path Validation**: Uses `is_valid_upload_path()` to prevent directory traversal

## Common Issues and Solutions

### Files Show as Offloaded but Not Served from CDN
**Cause**: S3 key path mismatch or missing database record
**Solution**: 
- Verify S3 key includes `wp-content/uploads/` prefix
- Check database record exists with correct `s3_key`
- Verify URL rewriter hooks are active

### "Could not load migration summary" Error
**Cause**: Summary loading logic dependent on detection endpoint
**Solution**: Load directly from Clockwork stats and sessionStorage, bypassing detection

### Database Table Missing
**Cause**: Table not created during activation
**Solution**: 
- Migration processor checks and creates table if missing
- Development Mode has "Create Database Table" button for manual creation

### Region Mismatch Errors (PermanentRedirect)
**Cause**: Region in database doesn't match actual bucket region
**Solution**: 
- Verify bucket region matches stored region
- Update region in settings if needed
- Region is stored per-record in database (from original offload)

## Migration from Other Plugins

The plugin supports migration from other offload plugins via the `clockwork-offloader-migrator` plugin.

**Migration Process:**
1. Detects source plugin settings
2. Migrates credentials and bucket configuration
3. Migrates attachment metadata (S3 keys, buckets, paths)
4. Records offloads in `wp_cloudbound_offloads` table
5. Preserves exact S3 key paths (including `wp-content/uploads/` prefix)

**Important**: Migration does NOT re-upload files. It only marks existing S3 files as offloaded in Clockwork's database.

## Multisite Support

### Network-Wide vs Per-Site Configuration
The plugin supports both network-wide and per-site configuration in multisite installations:

1. **Network Mode** (optional):
   - Network admin can enable network-wide settings
   - Settings stored in `wp_sitemeta` table
   - All sites use the same S3 credentials and configuration
   - Enabled via Network Settings page: `Network Admin > Settings > Clockwork Offloader`

2. **Per-Site Mode** (default):
   - Each site has its own settings
   - Settings stored in site-specific `wp_X_options` table
   - Each site can have different S3 buckets/credentials

### Settings Hierarchy (Multisite)
When retrieving settings, the plugin checks in this order:
1. wp-config.php constants (always highest priority)
2. Network settings (if network mode enabled)
3. Site-specific settings
4. Default values

### Database Tables
- Tables are created per-site using `$wpdb->prefix`
- Each site has its own `wp_X_cloudbound_offloads` and `wp_X_cloudbound_offload_queue` tables
- Network activation creates tables for the main site
- New sites get tables created via `wpmu_new_blog` hook

### Admin Menus
- **Single-site**: Settings page under `Settings > Clockwork Offloader`
- **Multisite (site admin)**: Settings page under `Settings > Clockwork Offloader`
- **Multisite (network admin)**: Network Settings page under `Network Admin > Settings > Clockwork Offloader`

## Important Notes for Future Development

1. **Provider Support**: Only AWS S3 and DigitalOcean Spaces are supported. Do not add Cloudflare R2 or Google Cloud Storage support.

2. **S3 Key Format**: Always include `wp-content/uploads/` prefix in S3 keys to match actual bucket structure.

3. **Database as Source of Truth**: The `wp_cloudbound_offloads` table determines if a file is offloaded. URL rewriter always uses S3 URL if record exists.

4. **Security First**: All code must follow WordPress security standards (nonces, capabilities, sanitization, escaping, prepared statements).

5. **Statistics Caching**: Statistics are cached for 5 minutes to avoid expensive queries on large datasets.

6. **Image Sizes**: Each image size (thumbnail, medium, large, etc.) is tracked separately in the database with its own record.

7. **Queue System**: Large bulk operations use the queue system to process in batches and avoid timeouts.

8. **Multisite Support**: 
   - Tables are created per-site in multisite installations
   - Supports both network-wide and per-site configuration
   - Network admin can enable network mode for shared credentials
   - Settings Helper manages the hierarchy automatically

9. **Settings Helper**: Always use `Clockwork_Offloader_Settings_Helper::get_settings()` instead of direct `get_option()` calls to ensure proper multisite support and settings hierarchy.

10. **URL Preview**: Dashboard feature that visually shows URL structure based on current settings. Helps users understand how their media URLs will be constructed.

## Performance Optimizations for Large-Scale Processing

The plugin is optimized to handle 10,000+ images smoothly:

### Batch Processing with Limit Checking
- **Time Limit Management**: Monitors execution time during batch processing (4-minute max per batch)
- **Memory Limit Management**: Tracks memory usage and stops before exceeding 200MB increase per batch
- **Automatic Resume**: Remaining items are marked as pending and processed in the next batch
- **Periodic Memory Cleanup**: Clears WordPress object cache and forces garbage collection every 10 items

### Adaptive Batch Sizing
- **Small Queues (< 1,000)**: Processes 10 items per batch (default from settings)
- **Medium Queues (1,000-5,000)**: Processes 20 items per batch
- **Large Queues (5,000-10,000)**: Processes 30 items per batch
- **Very Large Queues (> 10,000)**: Processes 50 items per batch for faster progress

### Automatic Retry Logic
- **Max Attempts**: Failed items are automatically retried up to 3 times
- **Smart Status Management**: Items that haven't exceeded max attempts are marked as pending for retry
- **Permanent Failures**: Only items that fail 3+ times are marked as permanently failed

### Efficient Database Queries
- **Chunked Queries**: Large attachment ID lists are split into chunks (1,000 IDs per query) to avoid MySQL IN clause limits
- **Lightweight Checks**: Uses direct SQL queries instead of `get_post()` for attachment existence checks
- **Lazy Loading**: Metadata is only loaded when needed, not upfront
- **Cache Management**: Clears attachment metadata cache after processing to free memory

### Queue Processing
- **Cron-Based**: Processes queue every minute via WordPress cron
- **Background Processing**: Runs automatically without user intervention
- **Progress Tracking**: Statistics updated in real-time for UI feedback
- **Auto-Unschedule**: Stops cron when queue is empty

### Memory Optimization
- **File Size Caching**: Uses `@filesize()` with error handling to avoid repeated filesystem calls
- **Metadata Cache Clearing**: Explicitly clears post meta cache after processing each attachment
- **Periodic Flushes**: WordPress object cache flushed every 500 items during queue insertion

These optimizations ensure smooth processing even on sites with 600,000+ media items.
